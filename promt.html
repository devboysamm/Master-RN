Backend API

Server behavior

  • Express server with JSON body parsing.
  • CORS allowlist includes production domains and localhost ports 5173 and 4173.
  • Health check endpoint: GET /health returns { success: true, message: "API is running" }.
  • Database schema is auto-initialized on server start via initializeDatabase.

Database schema

modules
- id (INT, PK, auto-increment)
- title (VARCHAR, required)
- description (TEXT)
- prerequisites (TEXT, comma separated)
- icon (VARCHAR, default: book)
- image_url (VARCHAR, nullable)
- background_color (CHAR(7), default #EAF2FF)
- order_index (INT, default 0)

lessons
- id (INT, PK, auto-increment)
- module_id (INT, FK -> modules.id, on delete cascade)
- title (VARCHAR, required)
- description (TEXT)
- content (LONGTEXT)
- read_time (INT, default 5)
- lesson_order (INT, default 0)

app_content
- id (INT, PK, single row with id=1)
- welcome_title (VARCHAR, required)
- welcome_description (TEXT, required)
- motivation_text (TEXT, required)
- motivation_quote (TEXT, required)

API endpoints

GET    /api/modules
GET    /api/modules/:id
GET    /api/modules/:id/lessons
POST   /api/modules
PUT    /api/modules/:id
DELETE /api/modules/:id

GET    /api/lessons/:id
GET    /api/lesson/:id   (alias)
POST   /api/lessons
PUT    /api/lessons/:id
DELETE /api/lessons/:id

GET    /api/app-content
PUT    /api/app-content

POST   /modules          (legacy)
POST   /lessons          (legacy)
PUT    /lessons/:id      (legacy)
DELETE /lessons/:id      (legacy)

Response shape

  • All successful responses are JSON: { success: true, data: ... } or { success: true, message: ... }.
  • Validation errors return 400 with { success: false, message: "..." }.
  • Not found returns 404 with { success: false, message: "..." }.

Important validation rules

  • Module title is required, background_color must be 6-digit hex.
  • Module image_url must be http or https when provided.
  • Lesson module_id and title required.
  • Lesson read_time and lesson_order must be numbers when provided.
  • App content requires all fields: welcome title/description and motivation text/quote.

Admin Panel (React + Vite)

Features

  • Dashboard: KPI cards for modules and lessons, latest lessons list.
  • Modules page: create, edit, delete modules; search and sort by title, order, lessons, time.
  • Lessons page: create, edit, delete lessons; order by module order and lesson order.
  • Settings page: API health check.
  • Live lesson preview with HTML sanitization and syntax highlighting.

Admin panel behavior details

  • Uses axios with retries and timeouts.
  • API base URL via VITE_API_BASE_URL (fallback to production URL).
  • Lesson editor supports templates for headings, paragraphs, lists, and code blocks.
  • Preview uses DOMPurify and highlight.js.

Mobile App (React Native + Expo)

Navigation

  • Bottom tab navigator: Home, Modules (stack), Bookmarks, Settings.
  • Modules stack: Modules list -> Module details (lessons) -> Lesson reader.

Screens and functionality

  • Home: welcome card, motivation card, module grid (first 6), view all.
  • Modules: full module list with icon/image, background color, lesson count, total read time.
  • Module details: module header, prerequisites chips, lessons list with bookmark and completion status.
  • Lesson reader: HTML rendering, code styling, bookmark toggle, mark completed.
  • Bookmarks: list bookmarked lessons, summary count and total minutes.
  • Settings: theme switcher (light/dark/system), local stats, reset local data.
  • Brand splash: animated intro screen on launch.

Local storage

  • Bookmarks stored as list of lesson IDs in AsyncStorage.
  • Completed lessons stored as list of lesson IDs.
  • Theme preference stored as light, dark, or system.

Mobile API client details

  • API base URL from EXPO_PUBLIC_API_BASE_URL or EXPO_PUBLIC_API_URL.
  • Fallback base URL: https://api.masterreactnative.dev
  • Request timeout: 30 seconds using AbortController.

Theming

  • Manrope font family with 400, 600, 700, 800 weights.
  • Light and dark color palettes defined in theme tokens.
  • Floating tab bar with card-like styling.

How to Connect Everything

  1. Start MySQL and create database course_learning (or set a custom DB name in backend env).
  2. Backend reads DB config from .env: DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME, DB_SSL.
  3. Backend auto-creates tables on start; no manual migration is required for dev.
  4. Admin panel points to backend via VITE_API_BASE_URL env.
  5. Mobile app points to backend via Expo public env or direct edit in the API client file.

Recommended .env examples

# backend-api/.env
PORT=5000
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=yourpassword
DB_NAME=course_learning
DB_SSL=false
DB_CONNECT_TIMEOUT=10000

# admin-panel/.env
VITE_API_BASE_URL=http://localhost:5000
VITE_API_TIMEOUT_MS=20000
VITE_API_RETRIES=2
VITE_SYNC_TIMEOUT_MS=25000

# mobile-app (Expo)
EXPO_PUBLIC_API_BASE_URL=http://localhost:5000
