3. Auth & tokens

Two token pair: accessToken (15 min, signed JWT) + refreshToken (30 days, opaque, stored in refresh_tokens table).

Token claims (access)

{
  "sub": "usr_01J9F7…",        // user id
  "role": "user" | "admin",
  "guest": false,
  "iat": 1715000000,
  "exp": 1715000900
}

Guest mode

If the user picks "Continue as guest" in the mobile Welcome screen, the client calls POST /v1/auth/guest and receives an access token with role:"user" and guest:true. Guest tokens are valid for 90 days. Bookmarks and progress are stored under the guest id but cannot be migrated to a real account later (advertise this in app UI).

Header format (all authed requests)

Authorization: Bearer eyJhbGciOiJIUzI1NiIs…

OAuth flow (Google / Apple / GitHub)

  1. Mobile uses expo-auth-session to get the provider's id-token.
  2. Client POSTs { provider, idToken } to /v1/auth/oauth.
  3. Server verifies the id-token with the provider's JWKs, creates or links the user, returns { accessToken, refreshToken, user }.

4. Error response format

Every error returns this shape. Never return raw stack traces or DB errors.

{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "Email is required",
    "details": {
      "fields": { "email": "required" }
    },
    "requestId": "req_01J9F7…"
  }
}

5. Database schema (MySQL 8)

IDs are ULIDs (CHAR(26)) prefixed by entity: usr_…, mod_…, les_…. Timestamps are DATETIME(3) UTC.

users

CREATE TABLE users (
  id           CHAR(30) PRIMARY KEY,             -- 'usr_' + 26 char ulid
  email        VARCHAR(255) UNIQUE,
  name         VARCHAR(120) NOT NULL,
  password_hash VARCHAR(255),                    -- null if OAuth-only or guest
  role         ENUM('user','admin') DEFAULT 'user',
  is_guest     BOOLEAN DEFAULT FALSE,
  avatar_url   VARCHAR(500),
  oauth_google VARCHAR(120),
  oauth_apple  VARCHAR(120),
  oauth_github VARCHAR(120),
  created_at   DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3),
  updated_at   DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  INDEX (oauth_google), INDEX (oauth_apple), INDEX (oauth_github)
);

refresh_tokens

CREATE TABLE refresh_tokens (
  id           CHAR(30) PRIMARY KEY,
  user_id      CHAR(30) NOT NULL,
  token_hash   CHAR(64) NOT NULL,            -- sha256 of the opaque token
  device_label VARCHAR(120),
  expires_at   DATETIME(3) NOT NULL,
  revoked_at   DATETIME(3),
  created_at   DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3),
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
  INDEX (token_hash)
);

modules

CREATE TABLE modules (
  id           CHAR(30) PRIMARY KEY,             -- 'mod_' + ulid
  slug         VARCHAR(80) UNIQUE NOT NULL,    -- e.g. 'm02-components-jsx'
  title        VARCHAR(120) NOT NULL,
  description  TEXT,
  order_index  INT NOT NULL,                   -- ordering in the path
  prereqs_json JSON,                              -- ['JavaScript','ES6','M01']
  read_minutes INT DEFAULT 0,                   -- auto-calc'd from lessons
  accent_color CHAR(7) DEFAULT '#F26A4A',
  icon         VARCHAR(40) DEFAULT 'layers',
  cover_url    VARCHAR(500),
  difficulty   ENUM('beginner','intermediate','advanced') DEFAULT 'beginner',
  status       ENUM('draft','review','published','archived') DEFAULT 'draft',
  created_at   DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3),
  updated_at   DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  INDEX (status, order_index)
);

lessons

CREATE TABLE lessons (
  id            CHAR(30) PRIMARY KEY,            -- 'les_' + ulid
  module_id     CHAR(30) NOT NULL,
  slug          VARCHAR(80) NOT NULL,
  title         VARCHAR(200) NOT NULL,
  order_index   INT NOT NULL,
  read_minutes  INT DEFAULT 5,
  content_html  MEDIUMTEXT,                       -- sanitized DOMPurify-safe HTML
  content_md    MEDIUMTEXT,                       -- raw markdown (admin source)
  excerpt       VARCHAR(280),                     -- shown in lists
  status        ENUM('draft','review','published','archived') DEFAULT 'draft',
  word_count    INT DEFAULT 0,
  view_count    INT DEFAULT 0,
  author_id     CHAR(30),
  published_at  DATETIME(3),
  created_at    DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3),
  updated_at    DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  UNIQUE (module_id, slug),
  INDEX (module_id, order_index),
  INDEX (status, published_at),
  FOREIGN KEY (module_id) REFERENCES modules(id) ON DELETE CASCADE,
  FOREIGN KEY (author_id) REFERENCES users(id) ON DELETE SET NULL
);

bookmarks

CREATE TABLE bookmarks (
  user_id    CHAR(30) NOT NULL,
  lesson_id  CHAR(30) NOT NULL,
  created_at DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (user_id, lesson_id),
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
  FOREIGN KEY (lesson_id) REFERENCES lessons(id) ON DELETE CASCADE

progress

CREATE TABLE progress (
  user_id      CHAR(30) NOT NULL,
  lesson_id    CHAR(30) NOT NULL,
  completed_at DATETIME(3),

  updated_at   DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (user_id, lesson_id),
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
  FOREIGN KEY (lesson_id) REFERENCES lessons(id) ON DELETE CASCADE,
  INDEX (user_id, completed_at)
);

chat_messages (AI chat history per user)

CREATE TABLE chat_messages (
  id          CHAR(30) PRIMARY KEY,
  user_id     CHAR(30) NOT NULL,
  role        ENUM('user','assistant') NOT NULL,
  content     MEDIUMTEXT,
  lesson_ref  CHAR(30),                            -- optional context lesson
  tokens_used INT DEFAULT 0,
  created_at  DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3),

activity_log (admin dashboard feed)

CREATE TABLE activity_log (
  id         CHAR(30) PRIMARY KEY,
  actor_id   CHAR(30),                            -- null = system
  action     VARCHAR(40) NOT NULL,             -- 'published','edited','archived'…
  entity     VARCHAR(20) NOT NULL,             -- 'lesson','module','user'
  entity_id  CHAR(30) NOT NULL,
  meta_json  JSON,
  created_at DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3),
  INDEX (created_at DESC),
  INDEX (entity, entity_id)
);
Admin-panel queries from activity_log drive the "Recent activity" feed and "Pinned drafts" panel on the dashboard. Inserting an activity row is mandatory in every mutating admin endpoint (create / edit / publish / archive).

10. Acceptance tests

The backend is "done" when these all pass. Map each test to its corresponding screen / feature in the mobile and admin designs.

Auth

  • Register → returns access + refresh token. Refresh exchanges for a new pair.
  • Guest login → token with guest:true. Bookmarks endpoint accepts it.
  • Login with wrong password 11 times in 15 min → 429 with Retry-After.
  • Logout invalidates the refresh token (subsequent refresh → 401).

Modules / Lessons

  • GET /v1/modules returns only status='published' for public, all for admin.
  • GET /v1/modules/:slug includes completedCount reflecting the caller's progress.
  • Admin reorder updates order_index atomically (one transaction).
  • Lesson HTML round-trips through DOMPurify on save → no <script> survives.

Bookmarks / Progress

  • Toggling bookmark twice ends with no row in the table.
  • Marking a lesson complete inserts completed_at. Module's completedCount updates.
  • scrollPct updates are debounced server-side: only the latest value within 5s window persists.

Admin

  • Non-admin token → 403 on any /v1/admin/*.
  • Every admin mutation inserts an activity_log row with the correct entity + actor.
  • Bulk publish 50 lessons → all-or-nothing transaction; on partial failure, response includes failed: [{id, reason}].
  • Dashboard /stats response time < 200ms p95 on a 10k-lesson seed.

Health

  • /health returns 200 if DB is reachable, 503 otherwise — never crashes the process.
